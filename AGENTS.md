# Niedax Generator agent guidance

## Architecture boundaries

- `apps/frontend` is presentation-only and calls relative `/api/v1` URLs. It never receives database credentials.
- `apps/backend` owns HTTP, authentication, authorization, and PostgreSQL access.
- `packages/calculation-engine` is deterministic, framework-independent TypeScript without I/O.
- `database` owns forward-only SQL migrations and manual backup/restore tooling.
- Caddy is the only host-published service. Do not publish Frontend, Backend, or PostgreSQL ports.
- Do not add cloud services, external runtime assets, telemetry, or product calculation logic at this stage.

## Required validation

Run `pnpm validate` for source changes. Run `pnpm validate:full` for Docker, networking,
database, authentication, backup, or infrastructure changes. If the pnpm shim is unavailable on
Windows, use `corepack pnpm` with the same arguments.

## Secrets and data

Never read secrets into logs, commit `data/`, or place credentials in environment examples,
Docker build arguments, browser code, or image layers. Runtime credentials are generated by
`pnpm setup` and mounted as Compose secrets from `data/secrets`.

## Docker and migrations

Preserve the two-network boundary and all hardening controls unless a verified platform
requirement is documented. Migrations are forward-only, timestamp-prefixed, checksum-protected,
owned by the migration role, and must pass `pnpm db:check`. Never reset the persistent database.
Never run `docker compose down -v` against the normal project.
